# 事务性话题关键词表（回复长度「维度 A」）
#
# 命中任一词 = 这轮是「办事」，预算走高基数；否则算「闲聊」，走低基数。
# 每行一个词，# 开头是注释，大小写不敏感，匹配的是「包含」而非整词。
# 网关启动时读一次；改完要重启网关才生效（不像 kb_keywords 那样每次请求重读，
# 因为它在热路径上，每轮读盘不值得）。
#
# 为什么需要它：预算原本只按「对方消息有多长」算，于是「NCC 据点在哪？」这种
# 最该说全的问题只能拿到 50 字，而灌水一大段闲聊反而顶格 220 字。
# 见 docs/superpowers/specs/2026-09-11-reply-length-design.md §1。
#
# 加词原则：宁可宽松。误判成「办事」的代价只是多给点额度；判漏的代价是
# 据点、价格、报名方式答不全 —— 而那正是 CLAUDE.md 3.7 记录过的事故类型。
#
# ⚠️ 种子抄自 mac-mini:~/ncc-kb/kb_keywords.txt（2026-09-11），但**此后独立演进**。
# 那份服务的是「要不要查知识库」，用途不同，别硬合并成一份。
